# SafePaste Final Project Report

## Problem and product value

Tonya, an e-commerce support agent, wants help from a public AI assistant but may paste a customer message containing a name, phone number or address. Manual checking depends on attention at the busiest point of her workflow. SafePaste adds a local review step: she enters one English message, inspects the proposed masks, and copies a sanitised version. The change is modest but concrete. Detection becomes a visible action before upload, and a mistaken mask can be reversed. This reduces exposure risk; it cannot guarantee that no personal information escapes. A missed span remains in the copied text unless Tonya catches it herself.

The project does not claim a new PII-detection model or a new product category. PrivacyScrubber is related prior work. SafePaste's contribution is an implemented, locally running workflow and an evaluation of whether combining rules and contextual detection improves coverage for this specific use case. Files, trade secrets, multilingual text, legal compliance decisions and enterprise-wide data loss prevention are outside its scope.

## AI choice and architecture

The task is to find and transform spans in supplied text. Structured identifiers suit patterns; names and free-form addresses require context. SafePaste therefore combines Presidio recognisers, including Singapore-specific patterns, with a pretrained GLiNER model stored on the device. It resolves overlapping detections, assigns typed placeholders such as `[PERSON_1]`, and masks lower-confidence model spans as `[POSSIBLE_PII_1]`. A restore map supports review but itself contains the original PII, so it must remain local and must not be logged or persisted.

I built the interface, pipeline, conflict handling, abstention policy, reversible masking and evaluation code. I reused Presidio and GLiNER instead of training a model. AI4Privacy data was used to map labels and select thresholds, not to update model weights. A cloud detector could reduce setup work, but it would require sending the very text being screened to another service. Local inference incurs model storage and startup costs, while avoiding an external per-call API charge. “Zero API cost” does not mean zero computing or maintenance cost. RAG would retrieve knowledge the task does not need; an agent would add tool decisions without improving span detection. A direct local pipeline is easier to inspect.

## Data, tuning and evaluation

The broad benchmark is the synthetic AI4Privacy PII-Masking-300K dataset. With seed 6201, I prepared 2,000 development records for mapping, rules and threshold choice, and 3,000 frozen records for the final comparison. Before running the frozen set, I fixed the mapping, detector rules, matching logic and GLiNER thresholds. The development sweep covered 30 threshold combinations. I selected a typed threshold of 0.55 and an abstention threshold of 0.40: lowering the latter added masks and review burden for a small gain in protective recall; raising the former reduced useful typed detections while increasing abstentions. This is threshold calibration, not fine-tuning.

I evaluated Presidio-only, GLiNER-only and Hybrid on the same frozen records. Exact-span recall requires identical character boundaries. Overlap recall gives credit for any shared characters, so it indicates detection but does **not** prove that every sensitive character was covered. Typed recall requires the correct entity label; protective recall also counts uncertain `[POSSIBLE_PII]` masks. Precision and abstention rate expose the cost of extra masks. One-to-one matching prevents duplicate predictions from claiming the same gold span. Labels outside the declared mapping are excluded explicitly. The data audit found one invalid development span, which the evaluator excludes and records.

The instructor also asked for text closer to Tonya's situation. I hand-authored 30 fictional Singapore-style support messages with local address forms, NRIC-shaped strings and informal phrasing. This set is reported separately and was not used for threshold selection. It checks plausible scenario behaviour, but its small size and my involvement in writing it create selection bias. Neither dataset measures how often a real agent accepts a wrong mask or overlooks a leak.

## Results and critique

My milestone target was 80% exact-span recall and an improvement over the rule-only baseline. The second condition was met; the first was not. On the 3,000-record frozen benchmark, Hybrid achieved **26.98% exact typed recall**, compared with 15.46% for Presidio-only and 11.60% for GLiNER-only. Hybrid's overlap protective recall was **47.44%**, compared with 21.85% and 28.04%. These are gains from complementary detectors, but 47.44% is far too low to claim comprehensive protection. Hybrid exact typed precision was 38.41%, below Presidio-only's 68.55%, and 10.05% of Hybrid predictions were abstentions. More coverage came with more false alarms and review work.

The per-label results explain the aggregate score. Hybrid exact typed recall was 98.90% for email and 96.73% for IP addresses, yet 0% for the 4,107 mapped government-ID spans in the broad benchmark. Address exact recall was only 8.65%. Many AI4Privacy labels represent generic international IDs or small address components, whereas the implementation recognises Singapore-shaped IDs and often returns a whole contextual address. This is both a detector limitation and a boundary mismatch. It would be misleading to treat overlap matching as a complete remedy: a partially masked address can still disclose information.

On the separate 30-message Singapore set, Hybrid achieved **92.45% exact typed recall** and **96.23% overlap protective recall** across 53 gold spans. That supports the intended support-text workflow, but it is not an estimate of production performance. The examples are fictional, few in number and aligned with the recognisers. After observing the low frozen result, I also calculated a narrower V2 mapping on the *saved predictions*. Hybrid then reached 47.86% exact typed and 65.14% overlap protective recall over 8,268 eligible spans. Because this mapping was defined after seeing the official result, it is a diagnostic sensitivity analysis, not a replacement for the original benchmark or evidence that the original target was met.

## Engineering difficulties and next steps

The hardest work was making the comparison fair: aligning two detectors and a many-label dataset, resolving overlapping spans, separating typed success from uncertain masking, and keeping the frozen set out of tuning. Local model loading also affects usability. In the frozen Hybrid run, the first record took about 14.2 seconds, while the remaining 2,999 averaged about 211 ms each. A live user therefore experiences a startup wait that a warm-only latency figure would hide.

The current product is a working prototype with clear rough edges. False negatives can expose PII; false positives can remove context that an assistant needs. The local restore map is sensitive, and the current evaluation has no user study or real operational data. I would next improve generic ID coverage and address boundaries, test on a larger independently authored and safely sourced support-text set, and measure how well people review and correct masks before copying. Until then, SafePaste is best understood as an additional checkpoint, not a substitute for organisational privacy controls.
