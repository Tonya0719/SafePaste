# SafePaste Final Analysis Draft

SafePaste addresses a common but easy-to-miss workplace privacy risk: a support agent copies customer text into a public AI assistant before noticing that the text contains personal information. In the target scenario, Tonya is an e-commerce support agent handling names, phone numbers, email addresses, addresses, order details and local identifiers. The harm is not only a formal compliance issue. A single accidental paste can expose customer data outside the organisation, create audit risk and reduce trust in AI-assisted support workflows. SafePaste is scoped as a local English-text review step before paste or upload. It is not designed to protect trade secrets, make legal compliance decisions, perform multilingual data-loss prevention or replace enterprise security controls.

The proposed solution is a local-first PII review tool. Before Tonya copies text into an AI assistant, SafePaste analyzes the text, masks detected spans and presents reversible placeholders. Structured PII is detected with Presidio-based recognizers for email addresses, phone numbers, IP addresses, credit cards, Singapore NRIC-shaped strings, unit numbers and postal codes. Contextual PII, especially names and addresses, is detected with a locally stored GLiNER model. A hybrid pipeline merges the two detector outputs and resolves overlapping spans. If GLiNER returns a span that is plausible but below the typed confidence threshold, SafePaste masks it as `[POSSIBLE_PII_n]` instead of assigning a specific type. The restore map lets the user recover false positives before copying the final text. PrivacyScrubber is relevant prior work and positioning context, but SafePaste does not claim category novelty; the contribution is the local orchestration, review workflow, reversible masking and evaluation.

The main business and technical trade-off is local processing versus cloud detection. A cloud API could simplify model hosting and updates, but it would require sending the same sensitive customer text to another external service. That weakens the product promise. Local processing avoids per-call API costs and keeps the privacy boundary simple: the text stays on the user's machine during analysis. The trade-off is that the user or organisation must manage the local model, dependency setup and runtime performance.

A second trade-off is rules versus contextual NER. Presidio is strong for structured identifiers with stable formats. It performs well on email and IP address spans and can be extended with Singapore-specific patterns. However, rules do not reliably identify names or free-form addresses. GLiNER helps with contextual entities, especially people and addresses, but it is weaker on exact boundaries and structured identifier classes. It may mark a broad phrase where the gold label marks a smaller component, or it may return contextual categories that are outside the final SafePaste label space. The hybrid system improves protective coverage by combining both approaches, but it also introduces more false positives and label errors.

SafePaste deliberately reuses established components instead of building every detector from scratch. Presidio and GLiNER provide the detection foundation, while the project builds the user-facing workflow, detector orchestration, abstention behavior, reversible redaction and evaluation harness. The project also deliberately avoids retrieval-augmented generation or agent planning. The task is detection and masking, not knowledge synthesis. Adding retrieval would not help Tonya decide whether text contains PII, and an agentic workflow would increase complexity without a clear privacy benefit. The product trade-off is between over-redaction and under-redaction. Over-redaction can remove useful customer context, while under-redaction can leak personal data. Reversible placeholders and explicit review reduce both risks by keeping the user in control.

The evaluation uses AI4Privacy PII-Masking-300K as a broad synthetic benchmark and a separate Singapore support-text stress set. The AI4Privacy data is synthetic and broader than Tonya's specific support workflow, so it is useful for stress-testing coverage but should not be treated as real production evidence. A fixed seed, 6201, was used to create a 2,000-record development split and a 3,000-record frozen evaluation split. The development split was used for label mapping, rule development and threshold selection. After the final configuration was frozen, the 3,000-record evaluation split was used once for the official comparison. A separate 30-record Singapore stress set was hand-authored with fictional examples and reported independently.

Three systems were evaluated: Presidio-only, GLiNER-only and Hybrid. The metrics distinguish exact matching from overlap matching and typed detection from protective detection. Exact typed recall requires the predicted span boundaries and label to match the gold span. Exact protective recall allows abstained `[POSSIBLE_PII]` spans to count if the range is correct. Overlap typed recall allows boundary overlap but still requires the correct label. Overlap protective recall allows overlapping abstained spans to count as protected. Precision and abstention rate are also reported. Predictions are matched one-to-one with gold spans so duplicate predictions cannot inflate scores.

On the AI4Privacy frozen evaluation, Hybrid performed best on recall but did not reach the 80% target. Presidio-only achieved 21.85% overlap protective recall. GLiNER-only achieved 28.04%. Hybrid achieved 47.44% overlap protective recall and 26.98% exact typed recall. This result shows that combining the detectors substantially improves coverage, but it also shows that the current system is incomplete for a broad synthetic PII benchmark. The main gap is not emails or IP addresses, where structured detection is strong. The largest misses are broad government identifiers and address components that are not fully covered by the current recognizers. GLiNER also often detects broad contextual spans while the benchmark uses fine-grained labels, which lowers exact typed scores.

The Singapore stress set produced a different result because it is closer to the intended product scenario. On 30 fictional support messages, Hybrid achieved 92.45% exact typed recall, 94.34% exact protective recall, 94.34% overlap typed recall and 96.23% overlap protective recall. Presidio handled structured local identifiers such as email, phone and NRIC-like strings, while GLiNER contributed names and address-like context. The remaining stress-set errors were mainly false positives and small boundary issues around address components. This suggests that the architecture is useful for Tonya-style support text, even though it is not yet strong enough for the full AI4Privacy label space.

The most important risk is silent failure. If SafePaste misses a span and the user trusts the tool too much, PII can still be pasted into a public system. False positives are also a real usability cost because they may remove context that the downstream assistant needs. The synthetic-to-real domain gap is another limitation: AI4Privacy and the hand-authored stress set cannot prove production performance on real support conversations. SafePaste is English-focused, does not detect trade secrets and does not replace enterprise DLP or legal review. The restore map contains original PII, so it must not be logged or persisted. Future work should add recognizers for passport numbers, driver licence numbers and generic government IDs, improve address span normalization, include human review of false positives and false negatives, and evaluate on a larger non-sensitive support-text dataset.
